## VideoCall Translate (native app)

A Capacitor-wrapped video call app with live speech captions and
translation. Two people join a room, see each other's video, and get
live captions of what the other person is saying, translated into their
own language.

### Layout

```
capacitor.config.json   Capacitor app config
www/                     Web app (HTML/CSS/JS) — the Capacitor webDir
  js/config.js           Runtime config (Supabase URL/key, ICE servers)
  js/languages.js        Supported languages for speech + translation
  js/permissions.js      Native mic/camera/speech permission handling
  js/speech-engine.js    Native speech-to-text (with browser dev fallback)
  js/translate-queue.js  Offline-safe translation client
  js/signaling-client.js Supabase Realtime client for signaling/captions
  js/webrtc-call.js      WebRTC peer connection + call controls
  js/app-lifecycle.js    Background/foreground handling + Android call service
  js/main.js             Wires all of the above into the UI
  js/vendor/supabase.js  Vendored supabase-js UMD build (kept local, not
                         fetched from a CDN, so it works offline)
android/                 Native Android project (generated by `cap add android`)
  .../CallForegroundService.java  Foreground service keeping calls alive
                                  in the background (camera+mic types)
  .../CallForegroundPlugin.java  JS-callable wrapper around the service
ios/                     Native Xcode project (generated by `cap add ios`)
supabase/functions/translate/  Edge Function: server-side translation
```

### What changed from the original web prototype

1. **Native shell** — Capacitor wraps `www/` into installable
   Android/iOS projects (`android/`, `ios/`). App id `com.gadson32.videocall`.
2. **Native speech recognition** — `js/speech-engine.js` uses
   `@capacitor-community/speech-recognition` (SFSpeechRecognizer on iOS,
   `android.speech.SpeechRecognizer` on Android) when running as a native
   app. The browser `SpeechRecognition`/`webkitSpeechRecognition` API is
   only used as a fallback for testing in a desktop browser — it does not
   exist inside a wrapped WebView, which is why the plugin is required for
   the app to work on-device at all.
3. **Real backend for Together mode** — signaling (WebRTC offer/answer/
   ICE) and caption relay run over **Supabase Realtime** channels
   (`js/signaling-client.js`): presence tracks who's in the room, and
   broadcast carries the signaling/caption payloads. This replaces
   `window.storage`, which only ever existed inside the preview sandbox,
   without you having to run/host a signaling server yourself.
4. **Server-side translation** — `supabase/functions/translate` is a
   Supabase Edge Function that calls MyMemory
   (mymemory.translated.net), a free translation API needing no key and
   no billing. This replaces `window.claude.complete`, which was
   specific to the sandbox. (An earlier version of this function called
   the Anthropic API instead — swapped out to avoid a paid dependency;
   see "Known gaps" for the tradeoff.)
5. **Native permissions** — `js/permissions.js` requests
   camera/microphone (via `getUserMedia`, which triggers the OS prompt
   inside the WebView) and speech-recognition permission (via the plugin,
   since iOS treats speech recognition as a separate grant from
   microphone access) with an "Open Settings" deep link
   (`capacitor-native-settings`) for when a permission was previously
   denied and the OS won't re-prompt.
6. **Background/lock-screen behavior** — captions pause when the app is
   backgrounded and resume on foreground (`js/app-lifecycle.js`). Call
   audio/video continuity is handled per platform: iOS via the
   `UIBackgroundModes: audio` entitlement in `Info.plist`; Android via a
   foreground service (`CallForegroundService`/`CallForegroundPlugin`,
   started on join and stopped on leave) with the `camera`+`microphone`
   foreground service types Android 14 requires.
7. **Offline resilience** — `js/translate-queue.js` persists every
   caption line (via `@capacitor/preferences`) the moment it's captured
   and retries translation on reconnect, so a dropped connection mid-call
   loses no transcript, only delays translation.

### Running it

**Supabase backend**

The app is wired to an existing project (`lufmsqbqxkubhvdsdpon`,
`js/config.js`'s defaults). To (re)deploy the translate function or point
at a different project:

```bash
supabase link --project-ref <your-project-ref>
supabase functions deploy translate
```

No secret is required to run as-is — MyMemory's anonymous tier needs no
key. Optionally set `MYMEMORY_EMAIL` (via `supabase secrets set
MYMEMORY_EMAIL=you@example.com` or the Dashboard's Edge Functions →
Secrets) to raise the free daily word limit from MyMemory's docs
(anonymous ~5,000 words/day → ~50,000 words/day with an email on file).
Never commit real secrets or paste them into a chat/AI tool regardless.

The function is deployed with `verify_jwt = true`, so callers must send
the project's anon/publishable key as `Authorization: Bearer <key>` (and
`apikey: <key>`) — that's what `js/translate-queue.js` already does using
`SUPABASE_ANON_KEY` from `js/config.js`. That key is meant to be public;
it is not the secret.

**Web client config**

To point at a different Supabase project, override before the other
scripts load:

```html
<script>
  window.__SUPABASE_URL__ = "https://your-project.supabase.co";
  window.__SUPABASE_ANON_KEY__ = "your-anon-or-publishable-key";
</script>
```

**Mobile app**

```bash
npm install          # also vendors supabase-js into www/js/vendor via postinstall
npx cap sync          # copies www/ into android/ and ios/, updates native deps
npx cap open android  # requires Android Studio
npx cap open ios      # requires Xcode (macOS only)
```

### Known gaps / next steps

- **TURN server**: only a public STUN server is configured
  (`js/config.js`). Calls across restrictive NATs/firewalls will need a
  TURN server added to `ICE_SERVERS` with real credentials.
- **Room-size enforcement is best-effort**: `signaling-client.js` checks
  Supabase presence state before joining a room, but a third client
  racing to join at the same instant could in principle slip in — there's
  no server-side gate anymore now that there's no custom server. Fine for
  personal use; revisit if this becomes multi-tenant.
- **Translation quality/reliability tradeoff**: MyMemory is free but
  lower-quality than an LLM-based translation and rate-limited
  (~5,000 words/day anonymous, ~50,000/day with `MYMEMORY_EMAIL` set).
  Fine for personal use with two participants; if that limit becomes a
  problem or translations aren't good enough, swap the `translate()`
  function in `supabase/functions/translate/index.ts` for DeepL's free
  tier (500k chars/month, needs a free account + API key) or an LLM API
  again — the request/response shape the rest of the app expects
  (`{ text, sourceLang, targetLang } -> { translation }`) stays the same
  either way.
- **Edge Function not yet live-tested from this environment**: this
  sandbox's outbound network policy blocks direct requests to
  `*.supabase.co` (and to `api.mymemory.translated.net`), so the deployed
  function's HTTP behavior (auth gating, translation, error responses) is
  verified by code review and by testing the equivalent logic locally,
  not by an actual end-to-end request. Test it for real from your own
  machine:
  ```bash
  curl -X POST "https://lufmsqbqxkubhvdsdpon.supabase.co/functions/v1/translate" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer <anon-key>" -H "apikey: <anon-key>" \
    -d '{"text":"hello","sourceLang":"en-US","targetLang":"es-ES"}'
  ```
- **Real device testing**: this environment has no Android SDK or Xcode,
  so `npx cap open android`/`ios` and on-device behavior (permission
  prompts, the foreground service notification, actual call quality)
  need to be run on your own machine.
- **App icon / splash screen**: currently the Capacitor default
  placeholder assets — swap `android/app/src/main/res/mipmap-*` and
  `ios/App/App/Assets.xcassets` before a store listing.
