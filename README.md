## VideoCall Translate (native app)

A Capacitor-wrapped video call app with live speech captions and
translation. Two people join a room, see each other's video, and get
live captions of what the other person is saying, translated into their
own language.

### Layout

```
capacitor.config.json   Capacitor app config
www/                     Web app (HTML/CSS/JS) — the Capacitor webDir
  js/config.js           Runtime config (server URLs, ICE servers)
  js/languages.js        Supported languages for speech + translation
  js/permissions.js      Native mic/camera/speech permission handling
  js/speech-engine.js    Native speech-to-text (with browser dev fallback)
  js/translate-queue.js  Offline-safe translation client
  js/signaling-client.js WebSocket client for the signaling/relay server
  js/webrtc-call.js      WebRTC peer connection + call controls
  js/app-lifecycle.js    Background/foreground handling
  js/main.js             Wires all of the above into the UI
android/                 Native Android project (generated by `cap add android`)
ios/                     Native Xcode project (generated by `cap add ios`)
server/                  Node backend: WebRTC signaling relay + translation API
```

### What changed from the original web prototype

1. **Native shell** — Capacitor wraps `www/` into installable
   Android/iOS projects (`android/`, `ios/`). App id `com.gadson32.videocall`.
2. **Native speech recognition** — `js/speech-engine.js` uses
   `@capacitor-community/speech-recognition` (SFSpeechRecognizer on iOS,
   `android.speech.SpeechRecognizer` on Android) when running as a native
   app. The browser `SpeechRecognition`/`webkitSpeechRecognition` API is
   only used as a fallback for testing in a desktop browser — it does not
   exist inside a wrapped WebView, which is why the plugin is required for
   the app to work on-device at all.
3. **Real backend for Together mode** — `server/` is a Node process
   (Express + `ws`) that relays WebRTC signaling (offer/answer/ICE) and
   caption events between the two participants in a room. This replaces
   `window.storage`, which only ever existed inside the preview sandbox.
4. **Server-side translation** — `POST /api/translate` on the same
   server calls the Anthropic API with a server-held `ANTHROPIC_API_KEY`.
   The client never sees the key. This replaces `window.claude.complete`,
   which was specific to the sandbox.
5. **Native permissions** — `js/permissions.js` requests
   camera/microphone (via `getUserMedia`, which triggers the OS prompt
   inside the WebView) and speech-recognition permission (via the plugin,
   since iOS treats speech recognition as a separate grant from
   microphone access) with an "Open Settings" deep link
   (`capacitor-native-settings`) for when a permission was previously
   denied and the OS won't re-prompt.
6. **Background/lock-screen behavior** — captions pause when the app is
   backgrounded and resume on foreground (`js/app-lifecycle.js`); call
   audio keeps flowing in the background on iOS via the
   `UIBackgroundModes: audio` entitlement declared in `Info.plist`.
   **Android does not yet have an equivalent foreground service** — the OS
   may suspend the call shortly after backgrounding until one is added.
7. **Offline resilience** — `js/translate-queue.js` persists every
   caption line (via `@capacitor/preferences`) the moment it's captured
   and retries translation on reconnect, so a dropped connection mid-call
   loses no transcript, only delays translation.

### Running it

**Backend**

```bash
cd server
npm install
ANTHROPIC_API_KEY=sk-ant-... CLIENT_API_KEY=some-shared-secret npm start
```

`CLIENT_API_KEY` is optional but strongly recommended — without it,
`/api/translate` is open to anyone who can reach the server and will burn
through your Anthropic quota. If set, the client must be configured with
the same value (see below).

**Web client config**

Before building, point the app at your server by setting these globals
(e.g. in a small script injected before `index.html`'s other scripts, or
via a build step):

```html
<script>
  window.__SERVER_URL__ = "wss://your-server.example.com";
  window.__API_BASE_URL__ = "https://your-server.example.com";
  window.__CLIENT_API_KEY__ = "some-shared-secret"; // must match server's CLIENT_API_KEY
</script>
```

Defaults point at `localhost:8787` for local development.

**Mobile app**

```bash
npm install
npx cap sync        # copies www/ into android/ and ios/, updates native deps
npx cap open android # requires Android Studio
npx cap open ios     # requires Xcode (macOS only)
```

### Known gaps / next steps

- **TURN server**: only a public STUN server is configured
  (`js/config.js`). Calls across restrictive NATs/firewalls will need a
  TURN server added to `ICE_SERVERS` with real credentials.
- **Android background calls**: add a foreground service (with a
  persistent notification) if calls need to survive backgrounding on
  Android — see the note in `js/app-lifecycle.js`.
- **Signaling server is single-instance**: `server/rooms.js` keeps room
  state in memory. Scaling to multiple server instances needs a shared
  store (e.g. Redis pub/sub) instead of the in-process `Map`.
- **App icon / splash screen**: currently the Capacitor default
  placeholder assets — swap `android/app/src/main/res/mipmap-*` and
  `ios/App/App/Assets.xcassets` before a store listing.
