# Answer Assist

A real-time answer assistant grounded in your own uploaded documents.
Upload SOPs/company docs, start listening during a live conversation
(interview or customer call), and tap "Get answer" to have Claude
synthesize a direct answer — but only from what's in your documents,
never from general knowledge or the web.

## Layout

```
capacitor.config.json    Capacitor app config
www/                      Web app (HTML/CSS/JS) — the Capacitor webDir
  js/config.js            Supabase URL/keys, app secret
  js/permissions.js        Native mic/speech permission handling
  js/speech-engine.js       Native speech-to-text (browser dev fallback)
  js/documents.js           Client-side text extraction (.pdf/.txt/.md)
  js/api.js                 Edge Function client
  js/main.js                 Wires everything into the UI
  js/vendor/                 Vendored supabase-js + pdf.js (no CDN)
android/, ios/              Native projects (generated by `cap add`)
supabase/functions/
  ingest-document/            Chunks + stores an uploaded document's text
  list-documents/              Lists uploaded documents
  delete-document/             Deletes a document (cascades to its chunks)
  ask/                          Full-text search + Claude-grounded answer
```

## How it works

1. **Documents**: upload a `.pdf`/`.txt`/`.md` file. Text is extracted
   client-side (pdf.js for PDFs) and sent to `ingest-document`, which
   chunks it (~800 chars, 100 overlap) and stores it in Postgres with a
   full-text search index (`tsvector`) — no embeddings API, no per-upload
   cost.
2. **Listening**: tap "Start listening" — native speech recognition
   (same plugin as the video-call project) transcribes continuously into
   a rolling buffer.
3. **Asking**: tap "Get answer" — the `ask` function full-text-searches
   your document chunks for the most relevant matches, then asks Claude
   to write a direct answer **using only those excerpts**. If nothing
   relevant was found, it says so instead of guessing. The rolling
   transcript resets after each answer so the next one only covers what
   was said since.

## Security model

This holds documents that can be sensitive (SOPs, internal company
info), so every Edge Function checks a shared secret (`x-app-secret`
header) in addition to Supabase's own anon-key gate — the anon key alone
isn't enough here, since it's extractable from the shipped app and would
otherwise let anyone who has it read your documents. The `documents` and
`document_chunks` tables have RLS enabled with **zero** policies, so the
anon/authenticated PostgREST roles get no direct access at all; every
read/write goes through an Edge Function using the service-role key.

This is a personal-use app, not multi-tenant — there's no user
authentication. If you ever wanted multiple people using separate
document sets, that would need real accounts (Supabase Auth), which
would be a meaningful rework, not a config change.

## Setup

**Supabase secrets** (this app shares the same project as the video-call
app — `lufmsqbqxkubhvdsdpon`):

```bash
supabase link --project-ref lufmsqbqxkubhvdsdpon
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
supabase secrets set APP_SECRET=<a-long-random-string-you-make-up>
```

Both are required — `ANTHROPIC_API_KEY` for answer synthesis (this
feature does need a paid API, unlike the video-call app's translation),
`APP_SECRET` for the client/function shared-secret gate above.

**Web client config** — set the same `APP_SECRET` value in the client so
requests actually pass the gate:

```html
<script>
  window.__APP_SECRET__ = "the-same-long-random-string";
</script>
```

Deploying/redeploying functions after changes:

```bash
supabase functions deploy ingest-document
supabase functions deploy list-documents
supabase functions deploy delete-document
supabase functions deploy ask
```

**Mobile app**:

```bash
npm install          # also vendors supabase-js + pdf.js into www/js/vendor
npx cap sync
npx cap open android  # requires Android Studio
npx cap open ios      # requires Xcode (macOS only)
```

## Known gaps / next steps

- **Not live-tested end-to-end from this environment**: this sandbox's
  network policy blocks direct requests to `*.supabase.co`. Extraction
  (PDF and plain text) was verified for real with actual files; the
  Edge Functions deployed without compile errors and their logic mirrors
  the already-tested `translate` function's patterns, but the full
  upload → search → answer round trip hasn't been run against live
  infrastructure. Test it for real once secrets are set.
- **Retrieval is keyword-based, not semantic**: full-text search matches
  words/phrases, not meaning — a question phrased very differently from
  the document wording may not retrieve the right chunk. If that's a
  problem in practice, the upgrade path is adding a real embeddings API
  (Voyage AI, OpenAI) and pgvector similarity search instead of
  `tsvector`, without changing the rest of the architecture.
- **No auto question-detection**: "Get answer" is a manual tap using
  whatever's been transcribed since the last tap — simpler and cheaper
  than trying to auto-detect when a question was asked, but means you
  have to actually remember to tap it.
- **Real device testing**: no Android SDK/Xcode in this environment —
  `npx cap open android`/`ios` needs to run on your own machine.
- **App icon/splash**: still Capacitor's placeholder assets.
